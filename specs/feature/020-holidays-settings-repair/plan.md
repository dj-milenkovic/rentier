# Implementation Plan: Holidays Settings Repair

**Branch**: `feature/020-holidays-settings-repair` | **Date**: 2025-07-15 | **Spec**: [spec.md](../../.specify/specs/020-holidays-settings-repair/spec.md)
**Input**: Feature specification from `.specify/specs/020-holidays-settings-repair/spec.md`

## Summary

Fix four interrelated issues in the Settings → Holidays screen: (1) the HTML parser cannot extract dates because it queries `<td>` while dates are in `<th>` elements, producing zero results on every import; (2) the DataGrid lacks a `DateOnly` ↔ `string` converter, preventing inline date editing; (3) NumericUpDown year fields are too narrow at `Width="100"`, clipping 4-digit values; (4) `HasUnsavedChanges` is not set after import, risking silent data loss. See [analysis.md](analysis.md) for full root cause analysis.

## Architecture Decisions

### AD-001: Fix Parser to Use `<th>` for Dates

**Context**: The HTML source uses `<th>` elements for dates and `<td>` for day-of-week, name, and type.
**Decision**: Change date extraction from `row.QuerySelectorAll("td")[0]` to `row.QuerySelector("th")`.
**Consequence**: Dates parse correctly. All 13 national holidays extracted for 2016 sample data.

### AD-002: Filter National Holidays by CSS Class and Type Text

**Context**: Response HTML includes all holiday types (`showrow` + `hiderow`). Only national holidays should be imported.
**Decision**: Filter rows by `class="showrow"` presence AND verify 4th column contains "National Holiday".
**Consequence**: Observances, seasons, and optional holidays excluded. Dual-filter is defensive against HTML structure changes.

### AD-003: DateOnlyToStringConverter for DataGrid Editing

**Context**: Avalonia DataGrid has no built-in `DateOnly` support for text column editing.
**Decision**: Create `DateOnlyToStringConverter : IValueConverter` using `"yyyy-MM-dd"` format. Use `DataGridTemplateColumn` with `CellTemplate` (TextBlock) and `CellEditingTemplate` (TextBox) in the AXAML.
**Consequence**: Users can type dates in `yyyy-MM-dd` format. Invalid input shows validation error via `BindingNotification`. Enter commits, Escape cancels.

### AD-004: Replace Strategy for Import (Not Upsert)

**Context**: When user imports holidays, the grid may already have entries.
**Decision**: Import clears all existing grid entries and replaces with imported data (per spec acceptance scenario 2.6).
**Consequence**: Simple, predictable behavior. No merge conflicts. User must save to persist.

### AD-005: MinWidth for NumericUpDown Year Fields

**Context**: `Width="100"` clips 4-digit years when spinner buttons are rendered.
**Decision**: Replace `Width="100"` with `MinWidth="120"` and add `FormatString="0"` to suppress decimals.
**Consequence**: Year fields always show full value. Controls can grow if layout allows.

### AD-006: Error Code Alignment

**Context**: Spec defines `HOLIDAY_IMPORT_FAILED`, `HOLIDAY_PARSE_ERROR`, `HOLIDAY_NOT_FOUND` but scraper uses `FETCH_FAILED`, `PARSE_FAILED`, `NO_HOLIDAYS_FOUND`.
**Decision**: Update scraper error codes to match spec. Update existing tests.
**Consequence**: Consistent API contract between Infrastructure and Desktop layers.
