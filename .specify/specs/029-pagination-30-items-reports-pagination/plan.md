# Implementation Plan: Pagination — 30 Items per Page & Reports Pagination

**Branch**: `feat/027-031-ux-improvements` | **Date**: 2025-07-16 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `.specify/specs/029-pagination-30-items-reports-pagination/spec.md`

## Summary

Standardises the page size to 30 items on the Filings page (up from 20) and introduces server-side pagination on the Reports page (currently returns all rows in a single call). Navigation controls (Previous / page indicator / Next) are added to the bottom of the Reports view, mirroring the existing Filings pagination layout. All changes follow established Filings pagination patterns — new `ReportsPageResult` DTO, paginated `GetReportsQuery` with in-memory slicing in the handler, and reactive pagination state/commands in `ReportsViewModel`.

**Constraints**: All data local-first; no new network calls; `decimal` for monetary values (unchanged)  
**Scale/Scope**: Two pages affected (Filings, Reports); ~10 files changed; ~200 net new lines
