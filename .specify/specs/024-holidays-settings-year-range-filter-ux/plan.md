# Implementation Plan: Holidays Settings — Year-Range Filter & UX Improvements

**Branch**: `004-holidays-year-filter-ux` | **Date**: 2025-07-15 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `.specify/specs/024-holidays-settings-year-range-filter-ux/spec.md`

## Summary

The Holidays settings page year-range selectors (`StartYear` / `EndYear`) currently have no visible effect on the holidays DataGrid — the `Entries` ObservableCollection is displayed unfiltered. This plan adds **in-memory reactive filtering** to derive a `FilteredEntries` collection from `Entries` that only includes holidays whose `Date.Year` falls within `[StartYear, EndYear]`. Complementary UX improvements include a range-specific empty-state placeholder, localized helper text explaining the dual purpose of the year range, and a visual separator between the controls area and the data grid.

**Approach**: Purely Desktop-layer (ViewModel + View) changes. No Domain, Application, or Infrastructure modifications. The ViewModel subscribes to `StartYear`, `EndYear`, and `Entries` changes via ReactiveUI's `WhenAnyValue` and `ObservableCollection.CollectionChanged`, rebuilding a filtered snapshot on each trigger. The View binds to `FilteredEntries` instead of `Entries` and uses conditional visibility for two distinct empty-state messages.

## Technical Context

**Language/Version**: C# 12 / .NET 8  
**Primary Dependencies**: Avalonia UI 11+, ReactiveUI, CommunityToolkit.Mvvm, FluentTheme  
**Storage**: SQLite via EF Core 8 (no schema changes for this feature)  
**Testing**: xUnit + FluentAssertions + NSubstitute  
**Target Platform**: Windows + macOS (cross-platform desktop via Avalonia)  
**Project Type**: Desktop application (Clean Architecture: Domain → Application → Infrastructure / Desktop)  
**Performance Goals**: Filter recalculation < 200 ms perceived (SC-001); collection size is tens to low hundreds  
**Constraints**: All filtering in-memory, no database round-trips; must not block UI thread  
**Scale/Scope**: Single page (HolidaySettingsView), ~50–200 holiday entries typical
