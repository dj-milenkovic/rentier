# Implementation Plan: Reports Inline Column Filters

**Branch**: `047-reports-inline-column-filters` | **Date**: 2025-07-15 | **Spec**: `.specify/specs/047-reports-inline-column-filters/spec.md`
**Input**: Feature specification from `.specify/specs/047-reports-inline-column-filters/spec.md`

## Summary

Add an inline filter row below the Reports DataGrid column headers, providing column-type-appropriate filter controls: text contains-search for Name/Importer, operator-based (>, <, =) filtering for Import Date/Email Date/Filing Count, and a dropdown for Status. Filters combine with AND logic, apply server-side with pagination, debounce text input at ~300ms, and include a "Clear filters" button. The pattern must be consistent with the Filings page (feature 045/046) and designed for reuse across both pages.

## Technical Context

**Language/Version**: C# 12, .NET 8  
**Primary Dependencies**: Avalonia UI 11+, ReactiveUI, CommunityToolkit.Mvvm, EF Core 8 (SQLite)  
**Storage**: SQLite via EF Core (local-first)  
**Testing**: xUnit + FluentAssertions + NSubstitute  
**Target Platform**: Windows + macOS (cross-platform desktop)  
**Project Type**: Desktop application (Clean Architecture: Domain → Application → Infrastructure/Desktop)  
**Performance Goals**: Filter results visible within 2 seconds; text input debounced at 300ms  
**Constraints**: Offline-capable, local-only data, <2s filter response for 1,000+ reports  
**Scale/Scope**: Hundreds to low thousands of reports; single-user desktop app

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- [x] Clean Architecture boundary is preserved (`Desktop -> Application -> Domain`; Infrastructure implements Application contracts only).
  - Filter UI state lives in `ReportsViewModel` (Desktop layer).
  - Filter criteria DTO defined in Application layer, passed through `GetReportsQuery`.
  - `IReportRepository` gains a new paged+filtered method; `ReportRepository` implements it.
  - Domain layer is untouched (no filter logic in entities).
- [x] All monetary/rate/percentage values are modeled as `decimal`.
  - No monetary fields in the filter. Filing Count uses `int`. Pattern supports `decimal` for future use.
- [x] All business dates are modeled as `DateOnly`; boundary conversions are identified.
  - Import Date and Email Date filters compare against `DateOnly` properties on `Report`.
  - Date input in the UI is parsed to `DateOnly` at the ViewModel boundary.
- [x] Security/privacy constraints hold: local-first data, OS credential store for secrets, no telemetry.
  - Filter state is ephemeral (in-memory). No data transmitted externally.
- [x] External network usage is limited to approved endpoints (IMAP and NBS) or explicitly justified.
  - No new network calls. All filtering operates on local SQLite data.
- [x] All I/O paths are async; UI work avoids blocking calls and uses reactive async command flow.
  - `LoadPageAsync` remains async. Filter changes debounce, then `InvokeCommand(LoadPageCommand)`.
  - Operator/dropdown changes invoke immediately (no debounce needed).
- [x] Tests and coverage impact are defined for Domain (rule/state coverage) and Application (>=90%).
  - Domain: No changes needed (no domain logic added).
  - Application: `GetReportsQueryHandler` tests updated for filter parameter forwarding.
  - Infrastructure: `ReportRepository` tests for filtered EF Core queries.
  - Desktop: `ReportsViewModel` tests for filter state, debounce, clear, pagination reset.
- [x] Feature work is mapped to an approved spec task under `.specify/tasks/`.
  - Task will be generated by `/speckit.tasks` after plan approval.
