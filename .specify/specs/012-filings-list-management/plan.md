# Implementation Plan: Filings List and Management UI

**Branch**: `feature/012-filings-list-management` | **Date**: 2025-01-08 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `.specify/specs/012-filings-list-management/spec.md`

---

## Summary

Replace the stub `FilingsViewModel` / `FilingsView` placeholder with a fully functional, paginated
DataGrid view of PP-OPO tax filings. The feature spans all four Clean-Architecture layers:

- **Domain**: Add `PaymentReference` (string?, max 200) to the `Filing` aggregate root and a
  `SetPaymentReference` mutating method.
- **Application**: Introduce `FilingFilterMode` enum, `FilingRowDto`, `FilingsPageResult`, and four
  CQRS handlers (`GetFilingsQuery`, `UpdateFilingStatusCommand`, `UpdatePaymentReferenceCommand`,
  `DeleteFilingCommand`). Extend `IFilingRepository` with `GetPagedAsync`.
- **Infrastructure**: EF Core migration 0009 adds a nullable `PaymentReference TEXT(200)` column.
  `FilingRepository` implements the new paged query using `.Skip()` / `.Take()` with optional
  `FilingFilterMode` predicate.
- **Desktop**: New `FilingRowViewModel` (per-row state) + full `FilingsViewModel` rewrite
  (IActivatableViewModel, ReactiveCommand.CreateFromTask). `FilingsView.axaml` replaced with a full
  DataGrid. All strings in `Strings.resx`. `CompositionRoot` updated with four new handler
  registrations.

**Primary Dependencies**: Avalonia UI 11, ReactiveUI, EF Core 8 (SQLite), ReactiveUI.Fody (NOT used — manual `RaiseAndSetIfChanged`), Microsoft.Extensions.DependencyInjection  
**Storage**: SQLite via EF Core; new nullable column `PaymentReference` in `Filings` table  
**Testing**: xUnit + FluentAssertions + NSubstitute; SQLite in-memory for infrastructure tests  
**Target Platform**: Windows + macOS desktop (cross-platform Avalonia)  
**Project Type**: Desktop application (Avalonia MVVM)  
**Performance Goals**: List load ≤ 1 s for ≤ 500 filings; filter switch ≤ 500 ms (SC-001, SC-006)  
**Constraints**: No UI thread blocking; all I/O via `async Task`; `decimal` for money; `DateOnly` for dates  
**Scale/Scope**: Single-user SQLite; no concurrent writes; 500-filing practical upper bound

## Phase 0: Research

> All NEEDS CLARIFICATION items were resolved in `clarify.md` via static codebase analysis
> before planning. No external research or tooling decisions are blocked. The findings are
> consolidated here for traceability.

### R-001 — DTO field set (resolved in clarify.md §Decision 1)

**Decision**: `FilingRowDto` is a 7-field projection (not a full entity mirror).  
**Rationale**: Matches the spec column list and follows `ImporterDto` subset pattern.  
**Field-name note**: `TaxPayable` ← `Filing.TaxPayableRsd` (rename at application boundary).

### R-002 — Pagination strategy (resolved in clarify.md §Decision 2)

**Decision**: Server-side pagination via `IFilingRepository.GetPagedAsync(filter, page, pageSize, ct)` using EF `.Skip()/.Take()`.  
**Rationale**: FR-014 mandates it; also required for filter/page-reset edge cases (SC-006).  
**Pattern**: Returns `(IReadOnlyList<Filing> Items, int TotalCount)` tuple; handler maps to `FilingsPageResult`.

### R-003 — VM injection pattern (resolved in clarify.md §Decision 3)

**Decision**: Direct constructor injection of `IQueryHandler`/`ICommandHandler` — no facade.  
**Rationale**: `ImporterSettingsViewModel` demonstrates this pattern with 6 injected handlers.

### R-004 — Post-mutation refresh strategy (resolved in clarify.md §Decision 4)

**Decision**: Full page reload (`LoadPageAsync`) after every mutation.  
**Rationale**: Required to handle filter-hiding edge case (spec §Edge Cases). Matches existing `ReloadImportersAsync` pattern.

### R-005 — PaymentReference persistence path (resolved in clarify.md §Decision 5)

**Decision**: `GetByIdAsync` → `filing.SetPaymentReference(ref)` → `UpdateAsync(filing)`.  
**Rationale**: Matches `UpdateImporterCommandHandler` load-mutate-save pattern; no new repo method.

### R-006 — ContentDialog pattern for delete confirmation

**Decision**: `ContentDialog` shown from inside `OnDeleteAsync` using `await dialog.ShowAsync()`.  
**Rationale**: Constitution §Coding Standards mandates async dialogs (`ShowDialog<T>`); no blocking `MessageBox`.  
**Implementation note**: The ViewModel will need a reference to the Avalonia visual root / parent window to call `ShowAsync`. The pattern used in `SyncMailboxCommandHandler` / other VMs can be inspected; if the project uses an `IDialogService`, use it — otherwise pass a `Func<Task<bool>>` confirmFunc in the command parameter.  
**Resolved**: The application uses a `ContentDialog` directly invoked from the command body with `Application.Current?.ApplicationLifetime` to locate the top-level window. Follow the same pattern used for `ReportsView` destructive actions if present; otherwise implement a simple `Func<Task<bool>>` confirmDelegate injected into `FilingsViewModel`.

### R-007 — FilingStatus display labels

**Decision**: Add `FilingStatus_Init`, `FilingStatus_Filed`, `FilingStatus_Paid` to `Strings.resx`.  
**Rationale**: FR-013 requires all user-visible strings in resx; enum values need display names.  
**Implementation note**: Use a value converter (`FilingStatusDisplayConverter`) that maps `FilingStatus` → localised string from `Strings`.

### R-008 — IncomeType display labels

**Decision**: Add `IncomeType_Dividend`, `IncomeType_Interest` to `Strings.resx` if not already present.  
**Rationale**: Consistency with FR-013; `IncomeType` is displayed in the Income Type column.

```csharp
// Rentier.Domain/Entities/Filing.cs
// Add property:
public string? PaymentReference { get; private set; }

// Add method:
/// <summary>
/// Sets (or clears) the payment reference code.
/// PaymentReference may be null (cleared) or a non-empty string up to 200 characters.
/// Throws DomainException if the string exceeds 200 characters.
/// The filing does NOT need to be in Filed status to call this method;
/// the read-only enforcement is in the UI layer (FR-008), not the domain.
/// </summary>
public void SetPaymentReference(string? reference)
{
    if (reference is { Length: > 200 })
        throw new DomainException("PaymentReference must not exceed 200 characters.");
    PaymentReference = reference?.Trim() is { Length: 0 } ? null : reference?.Trim();
}
```

**Domain invariant**: `PaymentReference` is null or a non-empty trimmed string of ≤ 200 characters.  
`AdvanceStatus` is unchanged.

### 1.3 Infrastructure Layer

#### `FilingRepository.GetPagedAsync` implementation

```csharp
// Rentier.Infrastructure/Repositories/FilingRepository.cs
public async Task<(IReadOnlyList<Filing> Items, int TotalCount)> GetPagedAsync(
    FilingFilterMode filter,
    int page,
    int pageSize,
    CancellationToken ct = default)
{
    var query = _db.Filings.AsNoTracking();

    if (filter == FilingFilterMode.Unpaid)
        query = query.Where(f => f.Status == FilingStatus.Init || f.Status == FilingStatus.Filed);

    var totalCount = await query.CountAsync(ct);

    var items = await query
        .OrderBy(f => f.FilingDeadline)
        .Skip((page - 1) * pageSize)
        .Take(pageSize)
        .ToListAsync(ct);

    return (items.AsReadOnly(), totalCount);
}
```
